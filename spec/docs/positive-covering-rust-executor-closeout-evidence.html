Implemented Contract

  • Polarityは文字列negativeとの完全一致だけをnegativeとし、missing、null、その他の値を non-negative laneへ排他的に送る。
  • off | negative | canary | allを実装し、canaryはcanonical SQLite pathとjob ID allowlistへbindingしたmanifestが必須である。不明なmodeやmanifest不一致はconfiguration errorになる。
  • Source support、active/draft Knowledge dedupe、value判定、applicability refinement、procedure repair/demotion、retryをRustへ実装した。
  • Finalizeへ渡す前にproject identityを検証する。Candidate metadataだけでなく、trusted agent-log sourceのprojectIdentityまたはprojectRootを共通identity contractで正規化し、 本当にidentityがない候補だけをinsufficient / project_identity_requiredとして隔離する。
  • External経路はquery生成、設定されたDuckDuckGo／Brave／Exaの順序と試行上限に従う検索fallback、 DNS全解決先検査、接続先pin、redirect再検査、SSRF block、byte/time/site上限、prompt-injection guard、untrusted/tainted/citation-required境界を持つ。
  • Evidence upsert、Finalize enqueue、queue transition、provider lease release、terminal eventを単一 SQLite writer transactionで確定し、同一candidateのEvidenceと同一EvidenceのFinalizeを増殖させない。
  • Coveringは専用laneで実行し、Findingまたはunpaused EpisodeがrunnableならCovering直後のprovider turnを他queueへ渡す。競合queueがなければprovider-pool capacity内で最大2件を並列実行する。
  • pendingまたはpaused Finalizeは次のCovering waveより先にlocal laneで処理する。Embedding retryの next_run_atが未来の場合だけprovider laneを止めず、runnableになった次のwave境界で再試行する。
  • queue executor-tickはwriter lockを取得できるoffline DBだけを1 tick処理し、live resident writerと競合する場合はfail-closedにする。

Implementation Notes

  • Promptは別の生成snapshotを増やさず、release build済みの.s11tnext/catalog.jsonを include_str!で直接embedしてja-JP segmentをrenderする方式にした。これにより生成物の 二重正本を避け、system-context:checkのdigest gateをそのまま共有する。

  • Liveのsearch順序はDuckDuckGo、Brave、Exaであり、providerごとの設定、credential、HTTP、parse failureを監査eventへ残して設定上限まで次のproviderへfallbackする。全provider失敗またはfetch失敗は 推測で継続せずretryable tool_failedへ戻る。Live live canaryではDuckDuckGo経路、offline copy canaryではBrave経路を実検証した。
  • External fetchのIP検査はIPv4-mapped IPv6とdeprecated IPv6 site-local rangeも非publicとして扱い、URL literalによるlocal-network guard迂回を回帰testで固定した。Response byte上限は4 MiBで、超過時は本文を使用しない。

Post-implementation Code Review

2026-08-20の実装後レビューで、concurrency、source parity、security、observabilityの追加欠陥を 修正した。Review後のcontractは次のとおりである。

  • Heartbeatと結果保存はqueue job、worker ID、provider lease IDの同一ownershipをtransaction内で 再検証する。Claimが回収・再取得済みなら古い結果を保存せず、idempotentな discarded / claim_ownership_changedeventだけを残す。
  • Worker threadの生成失敗、panic、heartbeat初期化失敗をretryable resultへ変換する。複数結果の persistenceは1件の失敗で残りを放棄せず、全件試行後に最初のerrorを返す。
  • Relative wiki_file keyはTypeScriptと同じpages/rootで解決し、canonical path外、symlink escape、非file、16 MiB超過、非UTF-8を拒否する。Markdown frontmatterと表示用 markerを正規化し、candidateのtoken rangeを最大8 window・各6,000 tokenで読み、実際に読めた rangeをreferenceへ保存する。
  • web_ingest URLはローカルpathとして扱わず、DNS全解決先検査、接続先pin、redirect 再検査、MIME検査、4 MiB上限、prompt-injection guardを通す。
  • SearchとLLM clientはredirectを追従せず、search responseとLLM responseにもbyte上限を適用する。 DuckDuckGo redirect URLのunwrapは正確なdomain boundaryだけを許可する。
  • Positive pipelineの全system contextでcandidate、source evidence、system/source metadataを未信頼 dataと宣言し、埋め込み命令、role/schema変更、policy更新、tool call、memory保存、判定抑制を拒否する。
  • queue inspectはallでも非default provider policyをunsupportedとして数え、 canarymanifestが欠落・不正・DB不一致なら全Covering backlogをfail-closedで unsupportedと報告する。
  • LaunchAgent rendererは全値をXML escapeし、placeholder置換を1 passに限定する。Source root、canary manifest、最大claim設定をresident processへ明示的に渡す。

Rollback

Stop conditionを検出した場合はLaunchAgentを CONTEXT_STILL_RUST_COVERING_MODE=negativeで再installし、running jobのterminal/retry transition後にresidentを1回restartする。Legacy workerは起動せず、正しく確定済みのrowは戻さない。
