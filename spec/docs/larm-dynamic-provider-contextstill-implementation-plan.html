ContextStill LARM動的Provider実装計画

ContextStillのbackground Queueが、SAAAおよび他サービスの処理を優先しながらLARMを利用するための 実装contractを定める。利用可否はProfile単位ではなく、 larm-service-activity.v1によるLARM全体のactivityで判断する。

LARM側のlive配備条件は Service Activity連携契約を正本とする。

1. 固定判断

  • SAAAへ通知、callback、webhookを追加しない。
  • GET /v1/activityをLARM全体の事前ゲートにする。
  • activity requestへqueryまたはbodyを付けない。
  • freshなidleかつactiveWorkloads === 0だけを実行可能とする。
  • Agent Connection createを最終admissionとし、activity snapshotを予約として扱わない。
  • Provider response完了後、次jobをclaimする前にactivityを再確認する。
  • 実行中jobはactivity変化だけでは中断しない。
  • 静的Providerへ暗黙にfallbackしない。
  • 動的Provider選択中は、旧static endpoint 127.0.0.1:44448への接続を禁止する。
  • credentialとclaimされたendpointをSQLiteまたは設定へ永続化しない。

2. 実行フロー

3. Service Activityの検証

responseは未知fieldを許さない。以下のいずれかに該当すれば、Connection作成とjob claimを行わない。

  • contractVersionがlarm-service-activity.v1ではない。
  • idleなのにworkloadが0ではない、またはactiveなのに0である。
  • reservationGuaranteedがfalseではない。
  • validForMsが固定値1,000msではない。
  • activeWorkloadsが0〜1,000,000のclient許容範囲外である。
  • retryAfterMsがidleで0、またはactive／drainingで固定値1,000msではない。
  • observedAtが期限切れ、非canonical UTC、または5秒を超えて未来である。
  • bootEpochまたはconfigRevisionが欠落・過大である。
  • HTTP非200、timeout、通信error、JSON parse errorである。

4. Profile discovery

Service ActivityはProfileの存在を保証しないため、新しいConnectionを作る直前に GET /v2/agent-profilesを実行する。catalog contractとrevisionを確認し、 contextstill-backgroundが一意に存在してdeprecatedではなく、設定audienceが catalogで許可される場合だけcreateへ進む。

ProfileのstreamingProtocolはSAAA Native WebSocketの任意広告であり、 HTTP SSEの可否判定には使用しない。ContextStillは openai.chat-completions.v1を確認し、JSON応答を要求するjobでは stream: falseを明示する。

5. Agent Connection lifecycle

  • POST /v1/agent-connectionsは201と202を受理する。
  • explicitAgentProfile: trueを送り、Profileの暗黙選択を禁止する。
  • allowFallback: falseを維持する。
  • deploymentPolicy: existing-onlyを維持する。
  • readyまでbounded pollし、claim responseをstrictに検証する。
  • request timeoutとcleanup marginを満たせない期限ならrenewして再claimする。
  • Queue idle、構成変更、protocol error、resident終了時にConnectionを解放する。
  • release失敗時もlocal credentialを破棄し、remote cleanupはTTLを最終防壁とする。

6. Queueとjob境界

activity確認はSQLite job claimより前に実行する。activityが実行可能で、ProfileとConnectionが readyになった後だけ、内部provider leaseとjobを同一writer transactionでclaimする。 Provider I/OはSQLite writerを保持せず実行し、lease fenceを確認して結果を保存する。

managerはresident tick間でConnectionを保持できるが、次jobを開始するたびにactivityを再取得する。 これにより、直前のContextStill jobが完了した後にSAAAまたは他サービスが処理を開始した場合、 ContextStillは次jobへ進まない。

7. Routing

  • findingCandidateはsource/vibeのrow種別に応じてdirect LARM routeを選ぶ。
  • episodeDistillerはdirect LARM routeを選ぶ。
  • LARMと静的targetが混在するpoolはfail closedとする。
  • TypeScript workerはLARM routeを実行せず、Rust residentだけが動的credentialを扱う。
  • 対象routeにdue jobがなければactivityをpollしない。
  • static方式はrouteのkind: staticまたは従来形式を明示的に選んだ場合だけ利用する。

resident起動時は、LLM routeごとに選択されたProvider kindを一度記録する。LARM routeでは control host、Agent Profile、audienceも記録し、tokenは記録しない。

8. Security

  • control URLはHTTP(S)のloopback、private、link-local、localhost、または.localに限定する。
  • redirectを追従しない。
  • control response size、protocol field、credential lengthを制限する。
  • credentialはzeroize対象としてmemory内だけで保持し、Debug出力でredactする。
  • claim endpointのhostとschemeをcontrol originへ拘束する。
  • claimされたendpointがloopbackのport 44448なら、Provider HTTP requestを送る前にprotocol errorとして拒否する。
  • CONTEXT_STILL_LARM_API_TOKENが設定されている場合だけ、activityを含むLARM control requestへBearerを送る。未設定時はAuthorization header自体を送らない。
  • 401はidleへ変換せず、static Providerへfallbackしない。

9. Test evidence

  • activity requestが正確にGET /v1/activityでquery/bodyを持たない。
  • idleかつcount 0の場合だけProfile discoveryとConnection createを一度実行する。
  • active、draining、HTTP error、timeout、未知field、stale responseではcreateしない。
  • contract mismatch、state/count矛盾、reservation claim、未来時刻、範囲外値を拒否する。
  • 次job境界でactivityを再取得し、既存Connectionを不要に再作成しない。
  • Queue idleではactivityを取得しない。
  • create、poll、claim、renew、DELETEと静的Provider routingに回帰がない。
  • optional Bearerの設定有無に応じてAuthorization headerの有無が一致する。
  • 401がfail closedになり、claimされたloopback port 44448を拒否する。
  • startupログがProvider kind、control host、Profile、audienceだけを含み、secretを含まない。
  • production相当のfake LARMでactivity、Profile discovery、create、claim、JSON completion、DELETEを通し、claimされたURL、model、短期tokenだけが使われる。
  • 同canaryで旧static endpoint 44448への接続試行が0件である。

10. Runtime activation gate

Source修正の完了とruntime有効化を分離する。2026-09-06時点のlive LARMでは GET /v1/activityがContextStillから利用できず、 contextstill-background Profileも未配備である。そのため設定は無効のまま維持する。

次の全条件を満たした後に限り、恒久Queue自動消化を有効化する。

  1. GET /v1/activityのlive contract確認。
  2. contextstill-background Profileのlive discovery確認。
  3. resident設定の対象routeをkind: larm-agent-connection、 connectionId: contextstill-backgroundへ切り替える。
  4. startupログで選択Provider、control host、Profile、audienceを確認する。
  5. idle/active/draining遷移と複数service共存canaryの合格。
  6. finding/episodeのOpenAI互換JSONまたはSSE応答品質canaryの合格。
  7. canary中のAgent Connection create、claim、completion、DELETEと、 127.0.0.1:44448への接続試行0件を確認する。
  8. Queue件数、failure率、lease、Connection解放の観測確認。
