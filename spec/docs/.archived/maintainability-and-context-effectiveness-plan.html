保守性とコンテキスト効果実証の改善

開始日：2026年9月6日。状態：実装完了。根拠は プロジェクト評価。

実装・計測結果は改善結果へ記録した。本文保持による改善、追加の待ち時間、独立した実作業評価が未実施であることを併記する。

対象と完了条件

設定画面、主要compile処理、queue処理の責務を整理し、巨大ファイルへの再集中を検知する。作業開始時点の未コミット変更を含むコピーとSHA-256を保存し、既存の設定操作・保存形式・MCP契約を維持する。

検索ケース評価のrepository identityと失敗判定を補強し、記憶なし条件と同じタスクを比較する評価を実行可能にする。入力・実装・provider・出力の対応、品質、誤誘導、時間、トークン、費用、未測定項目を記録する。合成fixtureによる回帰保証と、実providerを使ったタスク評価の証拠を区別する。

実施順序

  1. 基準となるソースと既存テストを確認する。
  2. 設定の変換・ルーティング・状態管理・画面各節を分割する。
  3. Rust compileの取得・生成・永続化・テスト、queueの独立した責務を分割する。
  4. 既存評価のscope、ラベル、degradedの扱いを修正する。
  5. 同一タスクの対比較、再現用manifest、結果集計、失敗時の終了コード、実験用fixtureを整備する。
  6. 保守性と効果評価の回帰チェックを通常検証に組み込み、結果と限界を別の証拠文書に残す。

評価の約束

期待値・判定規則を生成モデルへ送らない。missing metricを0へ置換しない。providerエラーや不完全なペアを成功から除外せず明示する。評価対象の知識集合、タスク集合、モデル、設定を固定し、記憶条件以外を揃える。ローカルで実行した結果から一般的な生産性向上率を断定しない。

稼働中データへの移行、daemon設定切替、秘密情報ストアの変更、製品配布は今回の2観点を改善する実装とは切り離す。評価は一時DB、read-only取得、明示した出力ファイルを使う。
