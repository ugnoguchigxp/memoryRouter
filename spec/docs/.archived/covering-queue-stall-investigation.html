Covering Queue Stall Investigation

Status

2026-08-19 JST時点のlive SQLite databaseとresident runtimeをread-onlyで調査した。停止原因はprovider障害、queue pause、実行時errorではない。Rust resident executorがpositiveまたはpolarity未設定の coveringEvidenceを実装対象外としてclaim候補から除外し、同時にlegacy TypeScript supervisorはresident ownerから撤去されているため、対象591件に実行主体が存在しない。

Live Evidence

  • Effective database: /Users/y.noguchi/Code/contextStill/data/context-still-core.sqlite
  • Resident process: context-stilld run、PID 76316、LaunchAgent com.context-still.daemon。
  • queue inspect --jsonはexecutorMode=rust_native、 executorRunning=true、rustCoveringMode=negativeを返した。
  • Coveringはpending=591、running=0、runnable pending 591。oldest pendingは2026-08-16 16:13:07。
  • Doctor warningはQUEUE_EXECUTOR_UNSUPPORTED_BACKLOG: coveringEvidence=591。 Queue inspectのreasonはrust_native_executor_partial_support。
  • 591件の内訳はpositive 554件、polarity未設定37件。全件 provider_policy=default、source kind vibe_memory、 attempt_count=0、delayなしである。
  • Queue controlはpaused=false。active provider leaseは0で、591件には last_errorもlast_outcome_kindもない。
  • Negative coveringはRust residentにより処理されている。直近のclaim/completed eventは 2026-08-19 09:02:38/09:03:18で、executor metadataは rustだった。現在negative pendingは0件である。
  • Legacy queue-supervisor processとLaunchAgentは存在しない。legacy logの最終更新は 2026-06-23 06:45:09 +0900で、最後はSIGTERM graceful shutdown timeoutで終了している。

Causal Chain

  1. Rust Finding executorがcandidateを作成し、positiveを含む後続 covering_evidence_queue rowを正常にenqueueする。
  2. Resident automationはCONTEXT_STILL_RUST_COVERING_MODE=negativeを既定にする。
  3. Rust executorの通常provider-pool claim対象はfindingCandidateと episodeDistillerだけで、coveringEvidenceを含まない。
  4. Coveringには別のcanary経路があるが、origin.polarity=negativeだけをclaimする。 Positiveとpolarity未設定rowは意図的にfail-closedで残る。
  5. Resident runtimeはTypeScript queue executorを起動しない。TypeScriptの queue:covering:onceはmanual recovery commandとしてのみ残っている。
  6. 結果として、negative rowは流れる一方、positive/missing-polarity rowは一度もclaimされず、 2026-08-16以降591件まで蓄積した。

Implementation Evidence

  • crates/context-stilld/src/domains/queue_lifecycle/executor.rsの rust_provider_executor_supports_queueは findingCandidate | episodeDistillerだけを返す。
  • 同fileのnegative covering claimはrequires_negative_candidate=trueを設定する。
  • crates/context-stilld/src/domains/queue_lifecycle/inspect.rsはnegative以外のrunnable Coveringをunsupported countへ含める。
  • src/cli/context-stilld-automation.tsはRust covering modeの既定値を negativeとし、legacy queue ownerをunloadする。
  • spec/docs/pub/configuration.mdもこのmodeを「Rust-native negative Covering canary」と記載し、offへ戻してもlegacy workerを起動しないと明記する。
  • commit 3fbf3deでresident Bun queue executionを削除し、commit 09fb4a6でunsupported queueをRust claim候補から除外した。その後のcommit e601db0はnegative Covering専用executorを追加したが、positive Covering parityは追加していない。

Ruled-out Causes

  • Queue pause: paused=false。
  • Backoff: 591件すべて現在runnableで、future next_run_atは0件。
  • Provider failure: 未claimのためattempt、error、leaseが存在しない。
  • Daemon停止: resident processとRust executorは稼働し、negative Coveringは同日完了している。
  • 投入不足: 591件がpendingで、Findingからのenqueueは継続している。

Impact

影響はCovering lane全体ではなく、positiveとpolarity未設定のCovering pathである。Negative pathは処理される。 ただし通常candidateの大半がpositiveであるため、ユーザーからはCovering全体が停止したように見える。未処理rowから evidence_coverage_resultsとfinalize_distille_queueが作られず、該当candidateはKnowledgeへ到達しない。

Recommended Resolution

詳細な実装順序、検証gate、canary、rollbackは Positive Covering Rust Executor Implementation Planで定義する。

  1. 恒久対応はpositive/default CoveringのTypeScript contractをRustへ移植し、provider-pool claim対象へ coveringEvidenceを追加する。positive、negative、polarity未設定のrouting fixtureと、Coveringから Finalizeまでのtransaction/state transition testをgateにする。
  2. backlogの短期解消が必要なら、既存のbun run queue:covering:onceをcontrolled manual recoveryとして使用できる。ただしlive DB mutationを伴うため、本調査では実行していない。
  3. Legacy continuous supervisorの復活はRust resident単独ownership contractと競合するため、恒久対応にしない。
